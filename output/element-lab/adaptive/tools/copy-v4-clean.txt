Bridgify Website Copy, v4 for design
Copy for every page in the website brief. Each page lists its URL, the SEO fields (title tag, meta description, H1), the copy for each section and its FAQ block.
How to read this doc
The studio leads the UX. Section order, layouts and the ideas in italics are suggestions, not instructions. Merge, split, reorder or replace sections wherever a better experience calls for it, and tell us if the copy needs to change to fit.
Product visual marks where we expect a visual of the product next to the copy, the way the current site shows the architecture diagram. That expectation is firm; what the visual looks like, and whether it's static, animated or interactive, is the studio's call.
Link lines give the clickable words in quotes, then the page or section they go to. They are instructions for the build, not live links.
Mockups of partner screens should use made-up brands unless a partner has approved the use of its brand.
Headline is the large display line in each section. Body is the supporting copy. Buttons are CTA labels.
H1 (SEO) is the page's single H1. On most pages it sits as a small eyebrow above the display headline, so search engines get the keyword and visitors get the clear line.
[CONFIRM] marks a fact Bridgify still needs to sign off before launch. [TBD] marks content the Bridgify team will supply. Please design around both.
FAQ blocks sit above the final CTA on each page, with FAQPage schema. Each answer reads on its own.
Spelling is American English throughout.

Experiences API FAQ
How does the Bridgify Experiences API work? You integrate once. Bridgify connects to multiple global marketplaces, aggregators and suppliers, normalizes their content into one schema and returns search, availability, pricing and booking through a single API. Your team builds the interface; Bridgify manages the supply behind it.
What is an API for travel? A travel API lets one system request travel content and bookings from another. A bank app, for example, can show live tours and take bookings without holding any supply itself. Bridgify's Experiences API covers tours, attractions, activities and events.
What is the difference between a travel API and a booking API? "Travel API" is the broad term for any API that serves travel content, such as flights, hotels or experiences. A booking API is the part that confirms and manages reservations. The Experiences API does both for experiences: discovery content plus booking and cancellation.
How do I choose the best API for activity inventory? Start with coverage: how many sources, destinations and categories are behind it. Then check real-time availability, content quality, and booking and cancellation handling. A multi-source API gives you more coverage and less dependence on one supplier.
Which experiences APIs offer real-time availability and pricing? Look for one that checks availability and price live when the traveler searches and again at booking, not from a cached feed. Bridgify's Experiences API returns real-time availability and pricing across 1M+ tours, attractions, activities and events from multiple suppliers, through one integration.
Why not connect to a single marketplace directly? Going direct gives you one catalog on one supplier's terms. The major marketplaces are strong networks, and they're inside the Bridgify catalog. Bridgify gives you several of them, plus direct suppliers, through one integration and one schema. If you want the deepest relationship with one supplier, go direct. If you want coverage and flexibility, that's what we do.

What is an attraction ticket API? An API that lets a platform sell entry tickets to museums, landmarks, theme parks and other venues: availability, prices, booking and the ticket itself. The Experiences API covers attraction tickets alongside tours, activities and events, from multiple suppliers.
What's the difference between an attraction ticket API and an activities API? An attraction ticket API sells entry to venues such as museums, landmarks and theme parks. An activities API sells things people do, such as tours, classes and day trips. Most travel brands need both. The Experiences API covers both, plus events, in one schema.
How do I add attraction tickets to a travel app? Connect to an API that already holds attraction ticket supply, then build search, ticket pages and checkout in your app. With the Experiences API, that's one integration for museums, landmarks and theme parks alongside tours and events. No developers? Link a White-Label Marketplace from your app instead.
What's the difference between a things-to-do API and a tours and activities API? The terms overlap. "Things to do" is the traveler-facing term and usually covers attractions, tours, activities and events. "Tours and activities" is the supplier-side term. The Experiences API covers the full range.
Does the API include event tickets? Yes. Live events, including concerts, sports and shows, sit alongside tours, attractions and activities.
How long does integration take? It depends on how much of the journey you build yourself. Your team integrates one API instead of one per supplier, and our team supports you through it. If you need to launch without development, the White-Label Marketplace goes live in 3 days.
